# MUKA-1 整理計画

## 現在の位置

本PRは8487839を基準に「共通512構文・IDと本文の維持・疎配列の解消」だけを扱います。
前の全機能案はPR #32 / archive/muka1-full-draft-70ac2caに保全し、公開対象として扱いません。
この整理作業では公開サイト・main・本番Worker・D1の変更は行いません。Secrets登録や公開操作は今回不要です。

## 今回含めるもの

- 元の512構文を、IDと本文を変えずにcatalog.jsへ分離。
- ゲーム、ランキング、履歴の共通Map参照。既存の投稿IDは255+submission.id。
- Workerの日次候補と画面を同じdailyIdsに統一。
- 既存URL、全128選択経路、ID、本文、既存APIの回帰検証。
- 重複は検査結果を報告し、独自の文章への差し替えは行わない。

## 明示的に未完了のもの

日替わり大会とその全国投票は、すべての日付で従来の256件から候補を選びます。
二択・ガチャ・主催者・個人大会は元の512件を利用できます。
512件からの日替わり大会・全国二択・定期王者・長期殿堂・新ポスター・長文画像の改善・匿名解析・正式公開は後続です。
このPRのテスト成功は本番移行やiPhone実機での動作保証を意味しません。

## 次のレビュー単位

1. このPR：共通データ、本文・ID・URL、旧APIの互換性。
2. DBと日替わり対応：本番スキーマの読み取り監査、バックアップ、移行計画、既存票内容の照合、日別候補の永続化。
3. 追加機能：全国二択、定期王者、解析、共有・ポスターを機能ごとに確認。
4. 公開：各段階のプレビュー、実機確認、Worker・Pagesの整合確認、作者ページ掲載。

## 日付と移行の原則

- 初回公開前の停止条件と、公開後の保守デプロイを分ける。
- 公開済みの日付に使った候補・ID・本文は後から変更しない。
- ソース内の「明日」に自動で切り替える仕組みは置かない。
- WorkerとPagesの公開時差でも候補が一致する方式を先に用意する。
- 本番の実スキーマ（索引・トリガー・ビュー・制約）を調べ、未確認のままvotesテーブルを置換しない。
- 件数の一致だけで移行成功としない。既存票のキーと値、承認済み本文を照合する。
- 512対応開始後は旧256専用Workerをそのまま復旧先にしない。拡張済みデータを読める復旧版を検証する。
- ADMIN_TOKENの維持と、通常の環境変数の維持は別に検証する。

## 検証方法

Node 24で `cd muka1-backend && npm ci && npm test`。
ブラウザ確認はリポジトリ直下で `python -m http.server 3000 --bind 0.0.0.0` を起動し、
`npx playwright install --with-deps chromium webkit` 後に `npm run test:browser`。
テストは本番投票を行わず、公開APIをモックまたはローカルSQLiteに置き換えます。
