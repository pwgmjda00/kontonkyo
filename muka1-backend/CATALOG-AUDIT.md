# 512構文の共通化・原本照合

基準はコミット `8487839` の `muka1-preview/index.html` にある旧 `pool` 256件と追加 `extra` 256件。

今回の共通化では、**512件すべての本文・ID・順序を原本どおり保持する。重複を理由とした文言変更は行わない。**

- 旧構文: ID `0`〜`255`。
- 追加構文: ID `1000255`〜`1000510`。
- 承認投稿: 従来どおり公開IDは `255 + submissions.id`。既存画面の投稿番号範囲 `1`〜`999999` は、公開ID `256`〜`1000254` に対応し、追加構文と重複しない。本番D1の既存データ検査や制約変更は今回の対象外。
- 共通データは512件のレコード配列と `Map<id,text>` で保持する。最大IDまでの疎配列を作らない。

## 原本一致の検証

SHA256は原本から抽出した値を `JSON.stringify` したUTF-8文字列に対する値。全レコードは `{id,text}` の順のオブジェクトで、旧256件の後に追加256件を並べる。

| 照合対象 | SHA256 |
| --- | --- |
| 旧256件の本文配列 | `80f6f3f79cf4b6de5e6730f121179458e7c471813f751e04fdbe934939983c64` |
| 追加256件の本文配列 | `306da7ef228914b53bd4f2048e8317dc3c1986eaa8ca288b2b5e57eafce29666` |
| 全512件のID・本文レコード配列 | `26eca4c8503e2ea7a0e9ee3d4db2aa738db6514872da367c1cb9ae612fbc7264` |

`node muka1-backend/tests/catalog.test.mjs` で、これらの固定値、ID整合性、投稿ID範囲、日付境界を検証する。

## 日替わり大会の範囲

**日替わり大会は過去・現在・将来のすべての日付で、既存256件・既存seed・既存シャッフルのまま。日付による自動切替は設けない。**

2020-01-01〜2036-12-31の各日について、従来方式と同じ8候補・順序になることを検証する。

512件を使う日替わり大会は今回未対応。後続作業で本番データとWorkerを確認し、過去日付の候補を維持する開始方法を別途決める。共通データ化だけで512件への日替わり移行やバックエンド更新が完了したとは扱わない。

## 重複検査の結果

`node muka1-backend/tools/audit-catalog.mjs` で全130816組を比較する。検査は報告のみで、文言を変更しない。重複の存在をテスト失敗にもしない。

完全一致は0組。NFKC正規化後に句読点・記号・空白を除いた一致は次の2組。

| ID | 原文 |
| --- | --- |
| 20 / 1000255 | 「その程度で傷つくならネット向いてないよ。」 / 「その程度で傷つくならネット向いてないよ」 |
| 31 / 1000319 | 「自分の機嫌くらい自分で取ろうよ。」 / 「自分の機嫌くらい自分で取ろうよ」 |

同じ正規化後のLevenshtein距離から求めた類似度が0.65以上で、上記の一致を除く組は次の4組。

| ID | 類似度 | 表現 |
| --- | --- | --- |
| 34 / 1000265 | 0.667 | 勝ち負けではないとしつつ自分の正しさ・結果を主張 |
| 50 / 1000435 | 0.800 | 期待していないから大丈夫 |
| 70 / 1000260 | 0.882 | そこまで説明しないと伝わらない |
| 73 / 1000481 | 0.842 | 真剣・真面目に受け取るとは思わなかった |

この指標だけで意味の重複を判定することはできない。例えば旧87/旧141は「意図せず好かれて困る」、旧150/追加1000332は「仕事や忙しさと返信速度を結び付ける」という意味の近さがある。これらも原文を保持し、編集上の採否は別途判断する。
