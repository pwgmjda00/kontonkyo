# ドパ・コレクターズ 運営ガイド（2026-10-31）

この機能は非換金の **無料デジタル報酬** です。実機確率の抽選や仮想玉／メダルの収支を賞金に交換する仕組みはありません。

## プレイヤー向け

- 🎟️ ステッカー: 初当たり1回、キラ2回、ホログラム5回、レジェンド10回。
- 🏅 称号: 当たり、機種収集、失敗、ハズレ、スコアなど17個。好きな獲得済み称号を装備。
- 📸 記念カード: 1080×1350 PNG。ブラウザ内で描画し、iPhoneの共有メニューまたはダウンロードで保存。個人情報の自動収集なし。
- 🏆 殿堂: GitHub Issuesで **明示的に本人応募** → 運営が人手で確認し、承認した投稿を週間コミュニティ展示へ。
- 🎬 演出案: 20機種のステッカーを解放したユーザーが絵文字演出テーマを応募可能。採用は運営次第。

プロフィールやコレクションはブラウザの localStorage に保存されます。Safariの閲覧データ削除やプライベートモードではデータが消えることがあります。別の端末への同期は未実装です。プレイの正当性をサーバー検証していないため、収集数・記念カード・反射スコアは **賞金や競技順位の根拠にしてはいけません**。

## 殿堂の運営方法

1. GitHubリポジトリ pwgmjda00/kontonkyo の Issues と Actions を有効にします。
2. **dopa-hall-approved** というラベルを作成します。デフォルトで自動作成されない場合はリポジトリの Issues → Labels → New label から作成してください。
3. プレイヤーはサイトの「🏆 殿堂掲載に応募する」から .github/ISSUE_TEMPLATE/dopa-hall.yml を提出します。個人情報を要求せず、ニックネームと同意が必須です。
4. 運営は公開ニックネーム・コメント・安全性・画像の適切さ・応募時の本人同意を確認し、掲載するIssueに dopa-hall-approved を付けます。承認はゲームスコアのサーバー検証を意味しません。
5. GitHub Actions の Weekly Dopa Community Hall が毎週月曜 **09:12 JST** に承認済みIssueを読み込み、data/hall_of_fame.json を更新します。必要なら workflow_dispatch で手動実行もできます。
6. データ更新コミットに連動して Build Dopa Button が実行され、サイトに反映します。最大12週、週15件、同じ公開ニックネームは週1件。
7. 掲載取り消し希望があれば該当Issueから承認ラベルを外し、手動実行します。アーカイブからも再生成で取り除かれます。

応募がない時は「初代殿堂の応募受付中！」を表示します。架空の優勝者・自動生成の人物や記録は載せません。

## 演出テーマの採用

dopa-theme.yml で応募された絵文字・台詞を読み、採用する案は運営が審査し、コードに取り込みます。20機種達成はクライアント表示であり、運営側で厳密な不正検証はできません。著作権や肖像権を侵害する画像を無断使用しないでください。

## 実装

- src/machineRewards.ts: 過去の獲得IDを移行する称号・ステッカー管理
- src/machineCard.ts: 機種画像のCanvasローカル生成、共有とPNGダウンロード
- src/RewardsHub.tsx, src/rewards.css: iPhoneのPUSHを優先する折りたたみUI
- src/MachineCelebration.tsx: 初獲得の絵文字演出とその場でのカード保存
- tools/publish_hall.py: 運営承認済みIssueだけを週次データにする
- tools/test_publish_hall.py: 同意・承認・URL判定の回帰テスト
- .github/workflows/dopa-hall-weekly.yml: 月曜の公開スケジュール
